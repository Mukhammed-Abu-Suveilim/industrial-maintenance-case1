# Соединение Codex с Colab через MCP

На 2026-10-18 проверен официальный
[googlecolab/colab-mcp](https://github.com/googlecolab/colab-mcp),
revision `b9ab3899e0f1fa493390b1fd6d54aa2e464ecdf1`, версия 1.0.1.
Сервер устанавливается через uvx в отдельное окружение Python 3.13.
Окружение проекта .venv Python 3.11 и зависимости моделей не меняются.

Фактически выполнены проверка `colab-mcp --help`, запуск сервера,
MCP handshake и получение tools. Доступен начальный инструмент
`open_colab_browser_connection`. Через отдельный MCP-клиент подключена
страница Colab; проверены создание, изменение и выполнение ячеек.
После смены runtime пользователем подтверждён Tesla T4 (15 360 MiB).
Пользователь вручную загрузил разрешённый архив: размер, SHA-256
и все 50 файлов подтверждены в Colab. Drive подключён, каталог
результатов создан; .venv Python 3.11.16 синхронизировано через uv.
В Colab пройдены 43 теста и Ruff изменённых файлов. Исполнитель
проектной тетради явно задаёт IPythonKernel и пустой список внешних
расширений: системный профиль Colab иначе требует google.colab,
которого нет в изолированном .venv. Первый запуск остановился до
обучения; его журнал сохранён. После исправления ядра модель отказа
прошла пять эпох, но отдельный Trainer прогнозов потребовал eval_dataset
из-за перенесённого eval_strategy=epoch. Процесс остановлен, checkpoints
остались на Drive; диагноз не обучался. Ошибка исправлена локально.
Пользователь затем выбрал CPU и сервер A100; Colab не продолжался.
Актуальная инструкция — [TRANSFORMER_SERVER.md](TRANSFORMER_SERVER.md).
Проверка первоначальной установки —
[verification.json](artifacts/preparation/colab_mcp_20261018/verification.json).

Сервер зарегистрирован в пользовательской конфигурации Codex с именем
`colab`. CLI и расширение Codex используют общую конфигурацию. Это
отдельная настройка Codex; открытая страница Colab в VS Code сама
по себе не предоставляет текущему агенту доступ к ней.

## Следующий шаг в VS Code

1. В панели Codex открыть меню с шестерёнкой → MCP servers.
2. Проверить, что `colab` включён, и выбрать Restart extension.
3. Продолжить этот диалог и попросить подключиться к Colab.
4. Инструмент сервера откроет специальную страницу Colab для соединения.
   Завершить вход Google и подтверждение подключения на этой странице.
5. После подключения проверить обновлённый список инструментов и
   доступность runtime/GPU. Только затем передавать подготовленную
   тетрадь и начинать согласованные два обучения.

Сервер требует локального MCP-клиента с поддержкой
`notifications/tools/list_changed`; успешный начальный handshake не
доказывает готовность динамических инструментов после входа.
В текущем сеансе динамические инструменты получены отдельным клиентом
официального MCP SDK; в нативном списке инструментов Codex они
не появились. Работающий клиент сохраняет соединение между вызовами.

Пример переносимой записи — [colab_mcp.example.toml](configs/colab_mcp.example.toml).
Этот пример не загружается автоматически из configs/. В установленной
записи указан фактический uvx.exe и локальный кэш; тайм-ауты запуска
и инструмента — 120 секунд. Это тайм-аут MCP-вызова, а не бюджет обучения.
Для длительного обучения режим выполнения следует выбрать по фактическим
инструментам подключённого Colab.

Настройка расширения описана в
[официальной документации Codex](https://learn.chatgpt.com/docs/extend/mcp).
Тетрадь и прежний способ запуска остаются в [TRANSFORMER_COLAB.md](TRANSFORMER_COLAB.md).
