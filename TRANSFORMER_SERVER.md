# RuBERT-tiny2: CPU и сервер NVIDIA

Одна исследовательская тетрадь для обоих режимов:
[04_rubert_tiny2.ipynb](notebooks/experiments/04_rubert_tiny2.ipynb).
Настройки — [04_rubert_tiny2.json](configs/04_rubert_tiny2.json).
На CPU проверяется полный протокол, а не сокращённая выборка.
Подтверждённый результат и команды приведены в PROJECT.md.
После полного прогона пользователь выбрал CPU для текущего этапа.
Разделы о сервере и NVIDIA сохранены как необязательная возможность.
Тетрадь дополнена проверками seeds 17/123 и синтетических формулировок.
При закреплённом stability_checks.reuse_fitted_batch она читает четыре
завершённых обучения; null означает четыре новых обучения.

## Сервер пользователя

Получены сведения: Ubuntu 20.04.6 LTS, NVIDIA A100 80 GB PCIe,
драйвер 550.144.03; nvidia-smi сообщает CUDA 12.4. JupyterLab работает
в браузере, создание .venv через uv разрешено. На /home свободно
12 GB, на / — 41 GB. Интернет доступен, возможности освободить место
нет. Исключительность выделения GPU пока не подтверждена.

Размер tmpfs 63 GB не является измерением свободной RAM процесса.
Перед установкой выполнить `free -h`, `df -h .` и `nvidia-smi`.
Разумно предусмотреть 20 GB свободного диска для окружения, кэша
и результатов; это запас, а не измеренный размер установки.
Каталог проекта, .venv и кэши лучше разместить на разделе с запасом
места. Выбор каталога на / требует прав записи: наличие свободного
места само по себе их не предоставляет. Ниже приведён вариант с /tmp
для окружения и кэша; он требует проверки доступности этого каталога.

## Что переносить

Одна загруженная ipynb без файлов проекта не является автономной
тетрадью. В Colab/Kaggle предустановленный kernel может иметь другую
версию Python; проект выполняется через собственную .venv Python 3.11
и scripts/check_eda.py, как и на сервере. Настройку конкретной платформы
следует закончить после её выбора; полный перенос на них текущей версии
ещё не проверен.

Предпочтительно загрузить один новый ZIP из artifacts/cloud,
созданный `uv run --no-sync python scripts/package_transformer.py`.
Распаковать в отдельный каталог, сохранив структуру путей.
Архив сам ничего не отправляет и содержит:

- pyproject.toml и uv.lock;
- notebooks/experiments/04_rubert_tiny2.ipynb;
- configs/04_rubert_tiny2.json и configs/eda_16_10.json;
- Data/Кейс_1_сложный_промышленность_15000.csv;
- Data/splits/eda_v1/membership.csv и manifest.json;
- src/industrial_maintenance/, tests/ и служебные scripts/;
- инструкции и только нужные manifest, таблицы выбора и validation-
  прогнозы закреплённых TF-IDF, числового CatBoost и prior;
- bundle_manifest.json с точным списком файлов и SHA-256.

Прогнозы контролей нужны для сравнений; перенос старых весов не нужен.
Для диагностики формулировок архив теперь также включает выбранные
модели RuBERT и два TF-IDF Pipeline, синтетические пары и review.
Поэтому новый архив значительно больше первоначального архива seed 42.
При reuse_fitted_batch=null включаются модели исходного seed 42;
новые seed обучаются в месте назначения. При закреплённом пути
включаются также выбранные модели seeds 17/123 для чтения без fit.
Архив не содержит .venv, секретов, баз MLflow и checkpoints оптимизатора.
Библиотеки и исходный кодировщик для новых fit скачиваются при настройке.
При отсутствии доступа в сеть
потребуется отдельно подготовить Linux wheels и веса; текущий архив
не является автономной установкой без сети. Windows .venv не переносить.

## Установка и проверка на сервере

Далее — инструкции для Ubuntu, подготовленные для сервера пользователя.
Их фактическое выполнение на A100 ещё не проверено. Все команды
выполняются в терминале JupyterLab из корня распакованного проекта.
Не использовать окружение conda base для ядра этого проекта.

```bash
# Проверить, что /tmp доступен и находится на разделе с запасом места.
df -h /tmp .
test -w /tmp
RUNTIME_DIR=$(mktemp -d /tmp/industrial-maintenance.XXXXXX)
export UV_CACHE_DIR="$RUNTIME_DIR/uv-cache"
export UV_PYTHON_INSTALL_DIR="$RUNTIME_DIR/python"
export HF_HOME="$PWD/.cache/huggingface"
uv python install 3.11
uv venv --python 3.11 "$RUNTIME_DIR/venv"
ln -s "$RUNTIME_DIR/venv" .venv
uv sync --locked --extra transformer-cuda
```

Последовательность предназначена для нового каталога без .venv.
Ссылка .venv позволяет проверкам и Jupyter использовать то же
окружение, физически размещённое в /tmp. Результаты остаются в
artifacts внутри проекта в /home. После очистки /tmp окружение нужно
создать заново; сохранённые в /home модели и метрики от этого не теряются.
Не сохранять исследовательские результаты в /tmp. Этот вариант
не применялся агентом на сервере пользователя.

Для CPU используется `uv sync --locked --extra transformer`.
Эти два extra взаимоисключающие; не применять --all-extras.
Обе сборки используют torch 2.9.1, transformers 4.57.6,
accelerate 1.12.0. CPU берётся из официального CPU index,
NVIDIA — из официального cu126 index PyTorch.

В torch 2.9.1 нет готовой сборки cu124, но есть cu126 и cu128:
[официальные сборки](https://pytorch.org/get-started/previous-versions/).
Внутри CUDA 12.x предусмотрена minor version compatibility с
ограничениями; драйвер 550 входит в соответствующее семейство:
[правила NVIDIA](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html).
Это не подтверждение выполнения всего проекта на данном сервере.
Локальный CUDA toolkit отдельно компилировать не требуется для нашего
кода. Не обновлять драйвер общего сервера самостоятельно.

Проверить архив до изменения DEVICE в тетради:

```bash
uv run --no-sync python - <<'PY'
import hashlib
import json
from pathlib import Path

# 1) Проверить каждый распакованный файл по manifest.
manifest = json.loads(Path("bundle_manifest.json").read_text())
for name, expected in manifest.items():
    actual = hashlib.sha256(Path(name).read_bytes()).hexdigest()
    if actual != expected:
        raise ValueError(f"Не совпадает SHA-256: {name}")
print(f"Проверено файлов: {len(manifest)}")
PY
uv run --no-sync python scripts/check_transformer_environment.py --device cuda
uv run --no-sync python -m unittest discover -s tests -v
```

Проверка устройства загружает закреплённый кодировщик и выполняет
прогноз только на явно синтетическом русском тексте для двух выходных
слоёв. Она не обучает модель на CSV и не оценивает test. При ошибке
CUDA сохранить сообщение; не менять автоматически версии или режим.

## Ядро и запуск в браузере

Зарегистрировать ядро в своём пользовательском JupyterLab:

```bash
uv run --no-sync python -m ipykernel install --user \
  --name industrial-maintenance-server \
  --display-name "Python 3.11 (.venv, industrial-maintenance)"
```

В существующем JupyterLab открыть проектную тетрадь и выбрать это ядро.
Рабочий каталог ядра — notebooks/experiments. Если нужны отдельный
JupyterLab и локальный порт, доступен scripts/start_jupyter.py;
способ доступа через VPN/проброс порта определяется настройкой сервера.

В начале тетради заменить `DEVICE = "cpu"` на `DEVICE = "cuda"`,
затем Restart Kernel → Run All. Выбор сохраняется в фактической
конфигурации запуска и MLflow. На CPU оставить cpu. Должен быть виден
ровно один GPU; при нескольких GPU задать CUDA_VISIBLE_DEVICES до
запуска Jupyter/ядра согласно правилам выделения ресурсов сервера.
Режимы не переключаются скрыто. Не запускать тетрадь одновременно дважды.

Для каждого seed два независимых обучения по пять эпох; только operator_log, полное
обучение кодировщика, AdamW 5e-5, batch 32/64, max_length 128, FP32,
seed 42, без поиска и ранней остановки. Лучшие эпохи выбираются по
validation AP/macro-F1. Затем выбирается F2-порог отказа. Test не
оценивается; старые модели не переобучаются. GPU другого типа может
дать другие последние разряды и результаты даже при одном seed.

## Что сохранить после выполнения

Новые результаты находятся в artifacts/experiments/rubert_tiny2_<UTC>/.
Для каждого обучения сохранены все checkpoints с состоянием AdamW,
выбранная модель с токенизатором, классы, train/validation-прогнозы,
журнал, метрики, конфигурация и исходный код. В summary.md — сводка;
manifest.json должен иметь status=completed. В исходном опыте seed 42
два обучения и девять сравнений; в проверке seeds 17/123 четыре обучения,
20 checkpoints и 18 сравнений. Все кодовые ячейки должны завершиться.
Синтетические формулировки сохраняются в отдельном каталоге
rubert_tiny2_wording_<UTC>; дополнительных обучений они не создают.

Скачать каталог этого запуска и выполненную тетрадь. При необходимости
перенести MLflow — весь artifacts/tracking/transformer после остановки
ядра; SQLite может содержать абсолютные серверные адреса, которые
не становятся автоматически локальными путями Windows. Решение по F2
хранится в model/decision_rule.json; from_pretrained не применяет порог.
Для воспроизведения продолжать пользоваться явным правилом >= threshold.

Оценки условны относительно выбора эпохи и порога на одной validation;
шесть общих текстовых шаблонов ограничивают выводы о новых формулировках.
Один seed не оценивает вариативность обучения.

## Если нужна аренда GPU

Для текущего RuBERT-tiny2 CPU уже достаточен: пять эпох на каждую
цель заняли около 200 с. A100 80 GB для этого опыта не требуется.
Для отдельного GPU-запуска можно рассмотреть одну NVIDIA с 16–24 GB.
На 2026-10-18 [Runpod](https://www.runpod.io/pricing) показывает
RTX A5000 24 GB за $0.27/ч и RTX 4090 24 GB за $0.89/ч для Pods;
это опубликованные ставки, а не подтверждённые свободные экземпляры.
Стоимость диска и действующую цену проверять перед запуском.
[Vast.ai](https://vast.ai/pricing) предлагает рынок GPU с меняющимися
ценами; для короткого первого запуска проще on-demand, поскольку
interruptible может быть остановлен провайдером. Платные ресурсы
агентом не создавались. Выбор платформы пользователь отложил.
