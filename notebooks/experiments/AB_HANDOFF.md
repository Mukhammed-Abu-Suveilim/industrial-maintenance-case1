# Передача A/B участнику C и LLM/RAG

Пользователь отвечает за A/B; C и LLM/RAG выполняет другой участник команды. Передача локальная: архив не загружался и сообщения участникам не отправлялись.

Путь к подготовленному набору и ZIP указан в [AB_RESULTS.md](AB_RESULTS.md). В наборе шесть закреплённых моделей: числовой CatBoost для failure_within_30d, числовой Random Forest для fault_type, две TF-IDF и два RuBERT-tiny2 seed 42. Числовые модели выбраны отдельно для каждой цели по прежним validation AP/macro-F1; seed 42 трансформера выбран как исходный закреплённый опыт, а не победитель трёх seed. Это передача A/B, не реализация C.

## Данные, классы и пороги

- train_features.csv и validation_features.csv: id и разрешённые нецелевые поля. id предназначен только для связи. Входы каждой модели перечислены в manifest.json: не передавать ей все столбцы автоматически.
- train_labels.csv и validation_labels.csv: отдельные целевые метки для обучения/оценивания C. **Не включать эти файлы в контекст LLM, поиск или карточки руководств.** Прогнозы переданы без y_true; метки нельзя восстанавливать из них как подтверждённый диагноз.
- development_membership.csv: исходные split и group_id только для train/validation. Test-строк в наборе нет. Полный исходный CSV и общая test остаются в основном проекте; внешний набор преподавателя отдельно не предоставлялся.
- required_route и severity не входят в признаки всех обучаемых систем, включая C. severity остаётся только в основном проекте для диагностики. Не восстанавливать её как дополнительный вход. Обе цели и id также не являются признаками.
- Положительный класс отказа — 1. Шесть диагнозов: bearing_wear, cavitation, imbalance, normal, overheat, seal_leak. Диагноз независим от бинарного решения отказа.
- В manifest.json хранятся точный run_id, исходный путь, классы, входы и порог. В классических бинарных моделях model.pkl сохраняет исходное правило, model_f2.pkl — готовое F2-решение без fit. Для B правило находится в model/decision_rule.json. Использовать `p(1) >= threshold`.

## Загрузка и представления для C

pyproject.toml и uv.lock скопированы из проверенного проекта. Установка — через uv в отдельную .venv; для CPU использовать существующую опцию transformer. Не устанавливать зависимости через pip или в глобальный Python. Исследовательские тетради и модуль загрузки находятся в основном проекте; в набор включён src с теми же функциями. Совместимость переносимой копии на чужой машине ещё не проверена.

Для классических моделей загружать joblib.load(model.pkl), сохраняя исходную предобработку. TF-IDF получает Series исходных строк operator_log; числовые Pipeline — DataFrame ровно из перечисленных входов. Вероятности соответствуют classes_, а не предполагаемому алфавитному порядку.

При использовании src из набора добавить его в sys.path в начальной ячейке: `sys.path.insert(0, str(Path.cwd() / "src"))`. Для load_cpu_predictor создать копию выбранной записи manifest.json и заменить run_path значением bundle_path: исходный run_path относится к основному репозиторию. Передавать функции только `features[spec["features"]]`, для TF-IDF преобразование в Series выполняется внутри. Порядок классов возвращается вместе с функцией вероятностей. Локальная проверка загружает все шесть моделей именно из передаваемого набора; работа на другом компьютере этим не подтверждается.

Для B использовать AutoTokenizer и AutoModelForSequenceClassification.from_pretrained с локальным каталогом model, local_files_only=True, trust_remote_code=False и attn_implementation="eager"; eval(), CPU и FP32 воспроизводят текущий протокол. Исходные max_length=128, padding внутри пакета, truncation=True. При расчёте вероятностей повторно использовать predictions_from_logits из text_transformer.py: он приводит logits к float64 и применяет scipy.special.softmax, затем общее правило классов/порогов. Это избегает неоговорённой замены вычислительного пути рядом с порогом.

Для C нужны **векторные представления кодировщика**, а не только вероятности B. У сохранённого BertForSequenceClassification доступен model.bert; его выходы last_hidden_state и pooler_output позволяют участнику C выбрать и документировать способ формирования представления. Размер скрытого состояния — 312, слоёв — 3. Применять соответствующий attention_mask. Веса и токенизатор переданы полностью; производные векторы здесь не рассчитывались и C не обучалась.

Две цели имеют отдельно дообученные кодировщики: они не являются одним общим набором весов. Участник C должен заранее описать, какой кодировщик использует для каждой цели, фиксирует ли веса, как объединяет измерения и представления, какие параметры выбирает на validation. Новый обучаемый масштабировщик/кодирование/классификатор C обучается только на train. Нельзя создавать производные признаки из отложенных целевых меток.

## Совместное итоговое оценивание

[Конфигурация протокола](../../configs/final_evaluation_protocol.json) закрепляет A/B и оставляет C/D незаполненными до решения ответственного участника. Это проект протокола, не подтверждение согласия участника. Test не открывать для настройки C/D или выбора лучших seed, моделей и порогов.

После фиксации всей команды оценить A/B/C/D на одинаковых id общей test. Сохранить вероятности, метки, классы, правила порогов, версии и время применения. Для отказа показать исходные 0.5 и фиксированные F2-пороги A/B; C выбирает свой порог только по validation. Для диагноза — argmax, включая normal. Для LLM передавать прогнозы и разрешённые наблюдения, не y_true. Сравнивать RAG и отсутствие RAG на одинаковых объектах и с одной моделью/настройками генерации.

Обязательные командные объёмы: минимум 200 test-объектов в обоих режимах LLM, минимум 100 вручную оценённых пар, оценённый поиск и компонентные абляции. Совместные ошибки маршрутизации и качество объяснений дополняют личный анализ A/B, а не подменяются им.
