# Прогноз отказов оборудования: модели A/B и продолжение C/RAG

Это общий репозиторий университетского проекта по кейсу 1: данные, выполненные тетради, код и результаты. Начинать с этого README; остальные документы нужны для подробностей.

**Готово:** EDA, логистическая регрессия, Random Forest, CatBoost, текстовый RuBERT-tiny2 и анализ A/B. **Далее:** другой участник реализует объединение признаков C и LLM/RAG. Итоговая test ещё не оценивалась.

## 1. Какие тетради открывать

В указанном порядке:

1. [EDA-16-10.ipynb](notebooks/eda/EDA-16-10.ipynb) — баланс классов, качество данных, повторы, выбросы и текстовые шаблоны.
2. [01_logistic_regression.ipynb](notebooks/experiments/01_logistic_regression.ipynb) — числовые и табличные входы, TF-IDF, поиск параметров и F2-пороги.
3. [02_random_forest.ipynb](notebooks/experiments/02_random_forest.ipynb) — Random Forest на числовых и табличных входах.
4. [03_catboost.ipynb](notebooks/experiments/03_catboost.ipynb) — CatBoost на тех же вариантах входов.
5. [04_rubert_tiny2.ipynb](notebooks/experiments/04_rubert_tiny2.ipynb) — трансформер, три seed, переформулировки, общий анализ A/B и материалы для продолжения.

Выводы ячеек сохранены: для знакомства достаточно открыть тетради. **Run All может повторить обучение.** Полные поиски первых трёх моделей — 66, 64 и 64 обучения соответственно. Некоторые режимы повторного чтения ожидают полный локальный архив кандидатов, который не хранится в Git.

[notebooks/01_eda.ipynb](notebooks/01_eda.ipynb) и [notebooks/team work/](<notebooks/team work/>) — исходные материалы команды для истории. Для текущего анализа использовать EDA-16-10.

## 2. Установка и открытие Jupyter

Нужны Git и uv. [Репозиторий приватный](https://github.com/Mukhammed-Abu-Suveilim/industrial-maintenance-case1): участнику команды сначала нужен доступ от владельца. Выполните команды в терминале; после `cd` рабочий каталог — корень проекта, где находятся README.md и pyproject.toml.

```text
git clone https://github.com/Mukhammed-Abu-Suveilim/industrial-maintenance-case1.git
cd industrial-maintenance-case1
uv sync --locked --extra transformer
uv run --no-sync python scripts/start_jupyter.py
```

uv создаёт проектную `.venv` с Python 3.11; скрипт запускает JupyterLab и регистрирует ядро **Python 3.11 (.venv, кейс 1)**. Выбрать это ядро для тетрадей. CPU — проверенный режим; NVIDIA не требуется. GPU и ограничения переноса описаны в [TRANSFORMER_SERVER.md](TRANSFORMER_SERVER.md).

В этой публикации находятся тетради с выводами, код, данные, конфигурации и результаты. **Обученные веса не входят в main:** они сохранены у автора A/B и передаются отдельно при необходимости. Git LFS для этого среза не нужен. Без весов можно читать тетради, анализировать сохранённые прогнозы и запускать синтетические проверки; загрузить готовые модели не получится. Новую машину отдельно проверить после установки.

## 3. Что уже получилось

Основные результаты — [AB_RESULTS.md](notebooks/experiments/AB_RESULTS.md). Все числа ниже относятся к **validation после выбора настроек**, а не к test:

- Отказ: числовой CatBoost AP **0,786742**, TF-IDF **0,442193**, RuBERT seed 42 **0,450304**. Установленного преимущества RuBERT над TF-IDF нет.
- Диагноз: TF-IDF и RuBERT macro-F1 **1,0**; лучший числовой контроль — Random Forest, **0,770903**. Шесть повторяемых текстовых шаблонов ограничивают смысл идеального результата.
- F2-пороги повышают полноту ценой ложных тревог. Они уже выбраны по validation; на test их не менять.
- Разобраны [30 ошибок](notebooks/experiments/AB_ERROR_ANALYSIS.md), сравнены equipment/severity и классы, измерено CPU-применение. Разбор выполнен агентом; человеческая экспертная проверка не заявляется.

Три seed и [24 проверенные переформулировки](notebooks/experiments/RUBERT_CHECKS_RESULTS.md) не установили устойчивого преимущества трансформера. AP и трапецеидальная PR-AUC сохранены раздельно. Последняя проверка: 54 синтетических теста; новые разделы выполнены в свежих ядрах.

## 4. Что делать участнику C и LLM/RAG

1. Прочитать EDA и [сводку A/B](notebooks/experiments/AB_RESULTS.md). Использовать общее разбиение и разрешённые входы.
2. Для C использовать обученный кодировщик B и числовые признаки. Конфигурации, токенизатор и прогнозы находятся здесь; обученные веса получить у автора A/B. Повторять поиск A/B для знакомства с результатами не требуется.
3. До запуска описать архитектуру C, входы и бюджет. Новую обучаемую предобработку и классификатор обучать только на train; настройки, эпохи и порог выбирать по validation.
4. Реализовать технический корпус, поиск и LLM с/без RAG. Отложенные целевые метки не передавать в поиск, карточки руководств или LLM. Технический корпус пока не предоставлен; его содержание не выдумывать.
5. Добавить компонентные абляции и сравнения на одинаковых объектах. По заданию LLM нужны минимум 200 test-объектов в обоих режимах и минимум 100 вручную оценённых пар.
6. Перед test дополнить [final_evaluation_protocol.json](configs/final_evaluation_protocol.json) фиксацией C/D. Затем совместно оценить зафиксированные A/B/C/D на одной test без настройки по её результатам.

За A/B отвечает пользователь; C и LLM/RAG — другой участник. Они ещё не реализованы здесь. Полная сверка — [REQUIREMENTS_AUDIT.md](REQUIREMENTS_AUDIT.md); источник — [PDF задания](Сложный_уровень_Кейсы_БЯМ_сложный_уровень.pdf).

### Как найти конфигурации моделей и прогнозы

[configs/ab_review.json](configs/ab_review.json) — индекс выбранных моделей. Каждая запись `models` содержит `key`, `run_path`, входы, классы и порог. Путь считается от корня проекта. Основные ключи:

- `catboost:A_numeric:failure_within_30d` — числовой контроль отказа.
- `forest:A_numeric:fault_type` — числовой контроль диагноза.
- `logistic:T0_tfidf:failure_within_30d` и `logistic:T0_tfidf:fault_type` — текстовые контроли.
- `rubert:B_text:failure_within_30d` и `rubert:B_text:fault_type` — исходные B seed 42, закреплённые заранее, без выбора лучшего seed.

В полном локальном запуске `model.pkl` содержит классическую модель, `model_f2.pkl` — бинарное решение с выбранным порогом; у B веса находятся в `model/model.safetensors`. Эти бинарные файлы не включены в GitHub. Конфигурация и токенизатор B, а также `model/decision_rule.json` с порогом отказа включены. `train_predictions.csv` и `validation_predictions.csv` содержат id, эталон, прогноз и вероятности. **Удалять `y_true` перед передачей прогнозов LLM.**

Для C у BertForSequenceClassification доступен кодировщик `model.bert`: выходы `last_hidden_state` и `pooler_output` позволяют получить представления, размер скрытого состояния — 312. Способ формирования представления выбирает и документирует участник C. Две цели имеют отдельно дообученные веса. Загрузка показана в тетради B и [text_transformer.py](src/industrial_maintenance/text_transformer.py).

## 5. Данные и ограничения

Основной CSV указан в [configs/eda_16_10.json](configs/eda_16_10.json); его имя и содержимое не менять. Разбиение — [Data/splits/eda_v1/membership.csv](Data/splits/eda_v1/membership.csv): train **10 655**, validation **2 193**, test **2 152**. Связь записей — `id`, группы бутстрэпа — `group_id`. Контрольные суммы находятся в конфигурации и manifest разбиения.

- Две независимые цели: `failure_within_30d` и `fault_type`, включая `normal`. Нулевой бинарный прогноз не отменяет диагноз.
- Во входах запрещены `required_route`, `severity`, `id` и обе цели. `id` — только связь; `severity` допустима для диагностики подгрупп.
- A_numeric: `operating_hours`, `temperature_c`, `vibration_mm_s`, `pressure_bar`, `load_ratio`.
- A_tabular_restricted: те же поля плюс `horizon_days`, `equipment`, `manual_id`.
- TF-IDF и B: только исходный `operator_log`.
- Обучение — только train. Test не использовать для выбора модели, seed, порога, инструкций LLM или корпуса.
- Точные журналы не пересекают части, но общие шаблоны пересекают. Разбиение не доказывает перенос на новые формулировки/машины. Порядок `id` не является временем.

## 6. Для чего остальные файлы

- **`configs/`** — настройки моделей, EDA, закреплённые пути и проект общего test-протокола.
- **`src/industrial_maintenance/`** — данные, предобработка, метрики, пороги, бутстрэп и функции моделей. Исследовательские циклы остаются в тетрадях.
- **`scripts/`** — запуск Jupyter и исполнение тетрадей, без отдельного исследования вне Jupyter.
- **`tests/`** — небольшие синтетические проверки выборок, вероятностей, метрик и сохранения.
- **`artifacts/eda/`** — результаты EDA; **`artifacts/experiments/`** — закреплённые сводки, прогнозы и выбранные модели. Автоматически выбирать «последний запуск» не нужно.
- **[PROJECT.md](PROJECT.md)** — подробное состояние, история и командный план. **[TERMINOLOGY.md](TERMINOLOGY.md)** — термины. **[CODING_STANDARDS.md](CODING_STANDARDS.md)** — правила кода. **[TEAM_EDA_FINDINGS.md](TEAM_EDA_FINDINGS.md)** — выводы команды.

Архивные тетради и подробные отчёты сохранены; читать их все для старта не требуется. Инструкции Colab/сервера относятся к отдельным способам запуска, а не к обязательным этапам установки.

## 7. Проверки и повторное выполнение

Синтетические проверки из корня, PowerShell:

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
uv run --no-sync python -m unittest discover -s tests -v
```

Linux/macOS:

```bash
PYTHONPATH=src uv run --no-sync python -m unittest discover -s tests -v
```

Чтение подготовленного раздела модели в свежем ядре:

```text
uv run --no-sync python scripts/check_eda.py notebooks/experiments/04_rubert_tiny2.ipynb --tag ab-review --timeout 1800
```

Заменить имя на одну из первых трёх тетрадей для её раздела. Используются закреплённые результаты, исходные обучающие ячейки не запускаются. Общий раздел `ab-summary` B также относится к прежней ZIP-передаче и не нужен для начала работы через Git.

В Git включены конфигурации выбранных моделей, исходные прогнозы и отчёты закреплённых опытов. Все обученные веса, optimizer/checkpoints, MLflow-базы, кэши, `.venv` и дублирующие ZIP остаются локально. Полные проверки сохранности исторического архива требуют локальной истории. Для нового обучения отдельно объявить конфигурацию и бюджет, выбрать новый каталог результатов и выполнить тетрадь; чтение результатов не выдавать за повторное обучение.
